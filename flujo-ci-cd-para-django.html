1. Resumen Ejecutivo del Proyecto

El presente informe documenta la implementación integral de un pipeline de Integración y Entrega Continua (CI/CD) para una aplicación backend basada en Django 4.2 y Django REST Framework (DRF) con base de datos PostgreSQL 13, orquestada mediante Docker y automatizada en la nube a través de GitHub Actions.

El ciclo implementado abarca la verificación estructural, ejecución autónoma de 28 pruebas unitarias, construcción y optimización de imagen Docker multi-capa, validación de salud de contenedores en tiempo de ejecución, empaquetado de artefactos versionados y simulación de despliegue en entornos limpios.

Se creó la rama ci-setup y el archivo .github/workflows/ci.yml para ejecutar las pruebas con Python 3.10. El job configuró caché de dependencias e invocó python manage.py test, logrando la ejecución de 28 pruebas exitosas sin errores en un tiempo inferior a 15 segundos.

3. Sesión 2: Automatización del Build con Docker

3.1 Dockerfile Optimizado con ENTRYPOINT

Se refactorizó el archivo app/Dockerfile para basarse en python:3.10-slim, optimizando el tamaño de la imagen y ordenando el copiado de capas para aprovechar el caché de Docker. 

FROM python:3.10-slim
WORKDIR /usr/src/app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1

RUN pip install --no-cache-dir --upgrade pip
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .
EXPOSE 8000
ENTRYPOINT ["sh", "/usr/src/app/entrypoint.sh"]
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]

Se incorporó app/entrypoint.sh, el cual realiza una verificación de socket TCP para esperar la disponibilidad de PostgreSQL antes de aplicar migraciones (python manage.py migrate --noinput) y levantar el servidor.

3.2 Orquestación con Docker Compose

El archivo docker-compose.yml integra el servicio de aplicación web (Django) y el servicio de base de datos relacional (PostgreSQL 13 Alpine) con healthcheck estricto (pg_isready) y volúmenes de datos persistentes: 

services:
  web:
    build: ./app
    command: python manage.py runserver 0.0.0.0:8000
    volumes:
      - ./app/:/usr/src/app/
    ports:
      - 8000:8000
    env_file:
      - ./.env.dev
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:13.0-alpine
    volumes:
      - postgres_data:/var/lib/postgresql/data/
    environment:
      - POSTGRES_USER=hello_django
      - POSTGRES_PASSWORD=hello_django
      - POSTGRES_DB=hello_django_dev
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U hello_django -d hello_django_dev"]
      interval: 5s
      timeout: 5s
      retries: 10

5. Recomendaciones Finales de Ingeniería de Software

5.1 Seguridad y Gestión de Secretos

  • Aislamiento de Credenciales: Migrar credenciales de base de datos y la clave SECRET_KEY hacia GitHub Actions Secrets (${{ secrets.SECRET_KEY }}) y no versionar archivos .env en repositorios públicos.
  • Ejecución sin Privilegios (Non-Root User): Declarar un usuario de sistema dedicado en el Dockerfile (ej. RUN adduser -D appuser && USER appuser) para prevenir vulnerabilidades de elevación de privilegios en el host.
  • Ajustes de Producción: Inhabilitar modo de depuración (DEBUG=0) y configurar ALLOWED_HOSTS con los nombres de dominio de producción autorizados.

5.2 Arquitectura y Rendimiento

  • Servidor de Aplicaciones WSGI/ASGI: Sustituir python manage.py runserver (diseñado únicamente para desarrollo) por servidores robustos y multi-hilo como Gunicorn o Uvicorn.
  • Multi-Stage Builds: Adoptar compilación en múltiples etapas en Docker para descartar compiladores y reducir el tamaño final de la imagen a menos de 150 MB.
  • Calidad Estática de Código: Añadir linters automatizados como Ruff o Flake8 en el pipeline antes de la fase de pruebas para garantizar el cumplimiento del estándar PEP 8.
